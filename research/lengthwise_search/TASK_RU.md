# Задача: точный интерфейс нижних оценок для R по фиксированной длине

## Цель

Сделать существующую R удобной целью для исследований: вместо отрицания
существования глобального зависимого семейства схем получить точную форму
`∃k ∀d ∃n ∀bounded-bundle ∃bad-promised-input`.
Классификация результата: Infrastructure — сила открытой гипотезы не уменьшается.

Базовый коммит: `ffba57655ac76e31f9e26304b2437139e47d4b08`.
Изменения находятся только в `research/lengthwise_search/`. Определения и
манифесты установленного пакета не меняются.

## Реализация, передаваемая на ревью

1. Ввести `SolverAt` и `LowerBoundAt` для существующих
   `SearchMCSPCompressionProblem` и `CircuitFamilyClass`.
2. Доказать глобальный solver ↔ наличие локального solver на каждой длине.
   Обратное направление использует разрешённый `Classical.choice`, а не
   предполагает существование равномерного алгоритма построения схем.
3. Доказать отрицание глобального solver ↔ существование локальной нижней оценки.
4. Специализировать эквивалентность к **неизменной** `OpenProblem.R`.
5. Дать лемму преобразования `LengthwiseR → OpenProblem.R`, которую затем можно
   передать существующему `ConditionalSeparation.close`. У этой леммы остаётся
   предпосылка: сама по себе она не является замкнутым доказательством R.
6. Проверить невырожденность concrete модели: bounded output tuple существует
   при всех k,d,n; witness width ≥4; константные таблицы удовлетворяют promise.
7. Добавить содержательные положительные и отрицательные примеры, полностью
   раскрытый контракт эквивалентности и транзитивный аудит аксиом.
8. Дать воспроизводимые команды с фактическими компиляторными квитанциями.

## Критерии приёмки

- Ровно один k выбирается перед всеми d; n — перед всеми наборами схем;
  плохой x выбирается после набора схем.
- Ошибка означает нарушение исходного relation всем выходным вектором.
  Сравнение с одним произвольно выбранным witness недостаточно.
- Размер ограничен отдельно на каждый выходной бит, не суммой размеров.
- Случаи n=0, n=1, нулевой ширины и отсутствия bounded tuples не теряются.
- Generic-теоремы не требуют дополнительных математических предпосылок.
- Не добавлены непроверенные допущения или незавершённые доказательства.
- Полный набор из 131 точного имени проверяется по импортированному окружению:
  19 исходных теорем, 19 зеркал, 24 определения/структуры/конструктора/проекции,
  24 независимых полных type/arity pin и 45 явно перечисленных compiler entries.
  Для каждого напечатан прямой axiom root; разрешены только
  `propext`, `Classical.choice`, `Quot.sound`. Равенство одних количеств не годится.
- Все модули компилируются с `-DwarningAsError=true` из свежих собственных исходников.
- Production guard отвергает `exact_R_of_lengthwise` именно из-за условного типа.
- Исходники core совпадают с inventory до и после проверки.
- Результат не описывается как доказательство R или P≠NP, конечный перебор
  bounded DAG либо ослабление исходного all-polynomial требования.

## Фактическая локальная интеграция и дальнейшие границы

В текущем source checkpoint шесть собственных модулей скомпилированы с
`warningAsError`, полный audit прошёл, а production exact-R guard вернул OS1
именно с `CLOSED exact expected type`. Это локальная компиляция с reuse
read-only зависимостей, не cold core build и не независимое ревью. Подробности
и исходная переданная история разделены в VALIDATION.md. Core, root Lake,
workflow/policy и существующий прямой путь через R не изменены. Ревью,
публикация и root CI остаются отдельными шагами. Другие пути исследования
P≠NP не исключаются: R здесь достаточна для одного условного маршрута, но
не заявляется необходимой для любой возможной теории разделения.

## Отдельная следующая задача (НЕ реализована и НЕ условие этого PR)

**Построить полиномиальный DAG-распознаватель точного tree-MCSP из поискового solver.**

Для того же k определить exact decision predicate
`F_k(n,x) := treeMCSPPredicate n (n^k+k) x`.
Входы — полные таблицы длины N=2^n. Доказать с явным учётом размеров:

```
polynomial bounded search solver at threshold k
  → polynomial bounded DAG decider for F_k
```

Построение: получить все выходные биты solver, проверить текущий concrete codec,
размер декодированной формулы и совпадение всей таблицы. На promised входах
проверка проходит по `solves`; на остальных никакая формула нужного размера
не может пройти проверку. Требуется построить проверяющие DAG и доказать
полиномиальную композиционную оценку, а не принять этот переход полем структуры.

Критерий результата: проверенная теорема
`F_k has no polynomial DAG decider → no polynomial search solver at k`.
Не утверждать обратное направление без отдельного доказательства. Этот мост
ещё не реализован в передаваемом коде. Следующий условный исследовательский
маршрут — связать его с псевдослучайными таблицами малых формул, явно сохранив
криптографическую предпосылку и количественные параметры безопасности.
